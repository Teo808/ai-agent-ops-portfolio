Action receipt report demo

A small Python demo for proving what happened after a workflow sends, submits, publishes, connects, or messages from a real account.

Portfolio home Python script Markdown source GitHub repo

The receipt rule

If a workflow touches a real account, the report should prove the expected account, visible account, intended action, boundary, confirmation, artifact URL, blocker state, and next step.

If those details are missing, the action is not verified. The honest report should say that instead of turning a click into a claimed result.

What the script tests

  1. A browser timeout before a social account can be verified.
  2. A public comment with visible confirmation and a page URL.
  3. An application that is staged but blocked at legal consent.

Why this is useful

It separates "clicked" from "verified."

It makes account proof part of the handoff instead of an assumption.

It records the allowed action boundary before the risky step.

It gives support or the next operator the first check instead of a vague success claim.

Run it

python demo/action_receipt_report.py --all

The default scenario intentionally returns "NOT VERIFIED." That is the right answer when browser control times out before account proof.
