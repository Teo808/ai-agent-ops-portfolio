Application run gate demo

A small Python demo for deciding whether a job lead should be applied to, staged, saved, or rejected before a workflow touches a real account.

Portfolio home Python script Markdown source GitHub repo

The gate

Before a job workflow submits anything, it should prove the lead is worth the action. Pay, schedule, commute, role fit, and legitimacy have to be clear enough. If the approved browser session is not verified, the workflow should stage the lead instead of pretending it applied.

This is built for an actor-first job search, where the income job supports auditions, self tapes, class, and creative work instead of crowding them out.

What the script tests

  1. A remote AI product support role that looks good but cannot be submitted because browser proof is missing.
  2. A local admin role with missing schedule details.
  3. A commission-only outreach role that should be rejected.
  4. A far commute with vague flexibility.
  5. A clear data and records role that can move to apply.

Why this is useful

It keeps the agent from padding application counts with weak leads.

It separates apply, stage, save, reject, and manual checkpoint decisions.

It protects acting time by making schedule and commute real gates.

It stops account actions when browser proof is missing.

Run it

python demo/application_run_gate.py --all

The first example returns "STAGE_NOT_SUBMIT." That is the right result when the role fits but the approved browser path is not verified.
