Browser attach health check demo

A small Python demo for deciding whether a real-account browser workflow can continue, open the target page, or stop before any risky action.

Portfolio home Python script Markdown source GitHub repo

The attach rule

Before an agent acts inside LinkedIn, X, a job portal, or any real account, it has to prove the browser tool is attached, the target page is visible, the expected account is visible, and no hard stop blocker is present.

If the tab list times out, the workflow stops. If the extension is reachable but only shows a welcome tab, the next step is to open the target site in that same verified browser session and check the account before acting.

What the script tests

  1. The extension times out before any tab list returns.
  2. The extension is connected, but only the welcome tab is visible.
  3. LinkedIn is loaded, the expected account is visible, and no blocker is present.
  4. X reaches an encrypted message passcode prompt before a DM can be sent.

Why this is useful

It stops the agent from treating a broken browser connection as a successful social action.

It separates extension health, target-page proof, account proof, and safety blockers.

It keeps user-approved fallbacks explicit instead of silently switching browsers.

It gives the next run a specific first check instead of a vague "browser failed" note.

Run it

python demo/browser_attach_health_check.py --all

The default scenario returns "STOP." That is the right result when the browser attach step times out before account proof.
