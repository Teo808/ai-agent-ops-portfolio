Cross-agent handoff checklist

The next agent should not make the customer repeat the whole story. It needs the current goal, state, action receipt, open risk, owner, and first safe resume check.

The handoff

  • Current goal: What is the user trying to get done now?
  • State: What has already happened, and what is the current status?
  • Actions taken: What did the previous agent read, change, or send?
  • Open risk: What could be wrong, stale, blocked, or unsafe to assume?
  • Next owner: Which person or system owns the next step?
  • Resume check: What should the next agent verify before acting?

Weak handoff versus useful handoff

Weak: "Help with the account." Better: "Resolve the duplicate charge without sending a refund twice."

Weak: "Issue is being handled." Better: "One refund request is pending. No second refund was sent."

Weak: "Nothing major." Better: "The payment record is still waiting on approval."

Weak: "Continue from here." Better: "Confirm the pending request before changing the payment record."

Why this matters

Shared context is useful only when it is current and easy to verify. A clean handoff gives the next agent a starting point, a boundary, and a clear reason to pause when the state is uncertain.

That applies to customer support, implementation work, browser automation, and any workflow that moves between tools or agents.
