Hermes run triage kit

A small tool for answering a simple question: did the agent actually finish the user's job, and what broke along the way?

The problem

A tool call is not the same thing as a completed task.

Hermes runs can touch browsers, files, MCP tools, memory, providers, and real account boundaries. A run can sound successful while the final user outcome is still unverified.

The response

Turn the messy run into a report someone can act on.

The triage kit reads a JSONL export or plain text log and produces a Markdown report with findings, risk level, tools seen, likely retry loops, and the next check.

What it checks

  • Stale browser references and recovery attempts
  • Tool errors, exceptions, and failed calls
  • Timeouts and deadline failures
  • Authentication and permission problems
  • Rate limits and quota signals
  • Possible secret or credential leakage
  • Verified success lines and final-state evidence
  • Repeated tool calls that may indicate a retry loop

Why I built it

I have been using Hermes for real workflows, so the failure modes are not theoretical. Browser refs go stale. Uploads fail. Authentication changes. A workflow stops at a judgment call. The useful response is not to hide the friction. It is to record what happened, separate the failure layer, and leave the next operator a safe place to resume.

This is a small proof item, not a claim that the whole problem is solved. It shows the kind of operator-side work I can do: notice a repeated failure, write a focused tool, test it, and make the result easy for someone else to inspect.

Run it
