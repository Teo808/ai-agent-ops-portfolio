Relationship outreach cooldown rule

Good outreach has a memory. If a company already has enough same-day contact, the next useful action is often to wait, learn, or improve the proof.

Portfolio home Markdown source GitHub repo

Why it exists

Job outreach should help the conversation move forward. It should not make the same ask from five angles because the tool can click fast.

A good relationship workflow checks who was contacted, what was sent, whether anyone replied, and whether the next message adds anything useful.

The send or wait check

Is there a new role, thread, reply, or real question?

Is this the right person for the ask?

Has this person or company already been contacted recently?

Would this feel reasonable if a human read the full history?

Useful next actions

  • Reply when a human answers.
  • Ask for the right path when a relevant contact accepts.
  • Save the thread when it points to a better proof item.
  • Wait when the company already has enough same-day contact.

Example report

The company already received a connection note, recruiter message, and public reply today. No new message was sent. The next run should check for a reply or connection acceptance before any follow-up.

Why this matters for AI agents

An agent with browser and messaging tools can spam faster than a person. The operator layer has to remember prior contact, platform state, account safety, and whether the next message helps. If it cannot explain why the next message is useful, it should not send it.
