Browser preflight decision demo

A small Python demo for deciding whether a browser automation workflow should send, submit, publish, or stop.

Portfolio home Python script Markdown source GitHub repo

The decision rule

Before an agent acts in a real account, it should be able to prove the browser context, the expected account, the action boundary, blocker state, and result proof.

If one of those is missing, the right answer is usually not another click. The right answer is a clean stop report with the first check for the next run.

What the script tests

  1. A social comment where the browser extension times out before account proof.
  2. A signed-in page where one public comment is inside the boundary.
  3. A job application flow that reaches a legal consent step and must stop for the user.

Why this is useful

It treats unknown account state as a stop condition, not a minor warning.

It separates routine friction from real blockers like legal consent or security checks.

It records the intended action and boundary before the risky click.

It gives support or the next operator a clear first check instead of a vague failure.

Run it

python demo/browser_preflight_report.py --all

The default scenario intentionally stops. That is the behavior I want from safe automation when the account cannot be verified.
