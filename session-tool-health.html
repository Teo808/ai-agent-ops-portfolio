Session tool health demo

A small Python demo for separating installed tool health from active session proof before a workflow touches a real account.

Portfolio home Python script Markdown source GitHub repo

The problem

A tool server can be healthy while the active agent session still cannot use it safely. That matters when the next action is a LinkedIn comment, X DM, job application, recruiter message, or any other real-account click.

If the current session cannot prove the page, account, boundary, and result path, a separate health check is only a repair clue. It is not permission to act.

What the script tests

  1. An active session times out, but a separate health check says the tool server exists.
  2. An active session works and the account is verified.
  3. The tool works, but the account is not verified.
  4. The tool works, but duplicate outreach risk says to wait.

Why this is useful

It stops the agent from treating a tool list as proof of a safe account action.

It gives support a cleaner blocker report: active session, health test, account proof, and duplicate risk.

It preserves relationship safety when the smartest move is to wait.

It turns blocked browser work into safe local proof instead of fake social activity.

Run it

python demo/session_tool_health.py --all

The first example returns "STOP_ACCOUNT_ACTIONS_AND_DO_SAFE_LOCAL_PROOF." That is the right result when a real-account action is blocked, even if a separate health test says the tool server exists.
