# Relationship outreach cooldown rule

Good outreach has a memory.

If someone already sent a connection note, recruiter message, email, or public reply to the same company today, the next smart action may be no new message. That is not passive. It is how the workflow avoids becoming noise.

## Why it exists

Job outreach should help the conversation move forward. It should not make the same ask from five angles because the tool can click fast.

A good relationship workflow checks the history first:

- Who was contacted
- What was sent
- Whether anyone replied or accepted
- Whether the new message adds anything
- Whether waiting is more respectful than nudging again

## The send or wait check

Before sending, answer these questions:

1. Is there a new role, thread, reply, or real question?
2. Is this the right person for the ask?
3. Does the message add useful context?
4. Has this person or company already been contacted recently?
5. Would this feel reasonable if a human read the full history?

If the answer is weak, wait or improve the proof instead.

## Useful next actions

A cooldown rule does not mean nothing happens. It means the next action should match the signal.

- Reply when a human answers
- Ask for the right path when a relevant contact accepts
- Save the thread when it points to a better proof item
- Improve the portfolio when no new message would help
- Wait when the company already has enough same-day contact

## Example report

The company already received a connection note, recruiter message, and public reply today. No new message was sent. The next run should check for a reply or connection acceptance before any follow-up.

## Why this matters for AI agents

An agent with browser and messaging tools can spam faster than a person. The operator layer has to remember prior contact, platform state, account safety, and whether the next message helps.

If the agent cannot explain why the next message is useful, it should not send it.
