# Candidate Profile

## Target roles

AI support, workflow operations, technical support, implementation support, and Forward Deployed Engineer roles around AI agents.

## Positioning statement

I build and test practical workflows around Hermes-style agents, OpenRouter and OpenAI-compatible providers, local models, MCP and tool integrations, project-scoped memory systems, browser automation, and agent operations stacks.

My strongest fit is testing, breaking, documenting, and improving real user workflows. I turn broken paths into clear ones through setup notes, debugging guides, field reports, executable checks, and clean handoffs that someone else can actually follow.

## Why call me back

I work from the operator side. I notice when setup instructions are unclear, memory retrieval drifts, a tool is authenticated but unavailable, a browser workflow breaks, or a provider changes behavior without a clear explanation. Then I isolate the failing layer, document what happened, and leave a safe verification path.

Successful AI deployment depends on more than model quality. It depends on whether the system can be installed, connected, trusted, debugged, explained, and improved in a real environment. That is the layer where I want to work.

- Hermes-style setup and workflow testing with memory, tools, and CLI integrations
- Provider and local model experimentation

- Project-scoped memory workflows using Obsidian and Supermemory-style patterns
- Browser automation, real-account boundaries, and safe stop conditions
- Public setup guides, incident runbooks, executable Python demos, and reproducible debugging paths
- Featured case study showing a scoped browser recovery and verified operator receipt

## Role fit

I am not positioning myself as an ML researcher. I am positioning myself as someone who uses, tests, breaks, fixes, documents, and understands AI agent workflows in real environments.

This fits AI support, agent deployment, field engineering, QA, technical support, implementation support, solutions support, and operations work around AI products.

## Operating style

| Situation | How I help |
| --- | --- |
| Agent setup is fragile | Reproduce the exact failure and write a reliable setup path |
| Memory recall is noisy | Separate stale or global context from project-scoped current state |
| Tool integration fails | Check authentication, transport, naming, server state, and minimal tool calls |
| Browser automation breaks | Capture page state, isolate selectors or login friction, and retry safely |
| A customer report is vague | Turn it into symptoms, environment, expected and actual behavior, and verification steps |
| A workflow changes hands | Leave current goal, state, actions taken, open risk, next owner, and resume check |
